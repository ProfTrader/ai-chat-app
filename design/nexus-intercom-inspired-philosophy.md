# Nexus Layout Concept

## Visual Thesis

Nexus should feel like a quiet operator console for AI-assisted customer work: structured like a professional inbox, softened by human conversation cues, and sharpened by one confident action color.

## Brand Philosophy

Nexus is not a dashboard mosaic. It is a focused workspace where a user can move from signal to response without changing mental modes.

The interface should borrow the useful rhythm of Intercom-style tools without becoming a replica:

- A persistent left rail gives users stable orientation.
- A second column holds the active queue: conversations, leads, contacts, or tasks.
- The center is the work surface, not a marketing canvas.
- A slim context panel explains the person, account, next step, and AI rationale.
- Status lives in the top bar so the user always knows whether they are drafting, reviewing, syncing, or ready to send.

## Design Principles

1. Work first, chrome second.
   Keep borders, labels, and controls quiet until the user needs them.

2. Human context beside AI output.
   AI suggestions should feel reviewed and accountable, not magical or decorative.

3. Dense, not crowded.
   Use compact rows, strong alignment, and restrained type scale so the product supports repeat work.

4. One clear accent.
   Use blue for active workflow and review state. Reserve amber for AI-generated or assisted content.

5. The composer is the hero.
   In chat or outreach flows, the draft/reply area should own the visual center.

## Layout Proposal

- Left navigation: workspace identity, primary modules, grouped shared views, and account status.
- Queue column: searchable conversation/contact list with state, owner, company, and last activity.
- Center surface: thread or sequence editor with a narrow top status bar and large writing canvas.
- Right context: contact/account detail, AI brief, next action checklist, and recent activity.

## Interaction Thesis

- Selecting an item slides the context panel content into place while the main draft remains stable.
- AI-assisted blocks use a small amber edge marker and a review chip instead of loud gradients.
- Hover states reveal secondary actions only inside the row or panel where they apply.
